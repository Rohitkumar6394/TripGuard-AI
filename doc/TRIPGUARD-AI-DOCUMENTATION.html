1. Overview

TripGuard AI combines travel planning with safety analysis. The core user journey:

  1. Users sign up / log in with email + password.
  2. They submit a trip form (origin, destination, dates, budget, transport, travel type, number of people, and preferences).
  3. The backend generates a deterministic demo plan containing an optimized day-wise itinerary, cost breakdown, hotel suggestions, weather insight, safety score with alerts, and emergency contact info.
  4. Results are saved to MongoDB and shown in the dashboard.
  5. A Safety Chatbot answers travel-safety questions in the context of the user's saved trip (emergency numbers, night travel, documents, transport, live weather).
Note: The current trip generator uses deterministic demo logic, not a live AI/LLM provider. A real provider can be connected later without changing the MongoDB structure.

6. Backend API Reference

Base URL: http://localhost:4000

MethodEndpointAuthDescription
POST/api/auth/signupNoCreate an account. Body: { name, email, password }
POST/api/auth/loginNoLog in. Body: { email, password }
GET/api/auth/meYesCurrent authenticated user.
GET/api/healthNoHealth check: { ok, database }.
GET/api/weather?location=...NoLive weather + 5-day forecast (Open-Meteo).
POST/api/chatYesSafety question. Body: { message, tripId? }
POST/api/tripsYesCreate a trip plan. Body: { origin, destination, startDate, endDate, budget, transportMode, travelType, people, preferences, fullName?, email? }
GET/api/tripsYesList user's trips (newest first).
GET/api/trips/:idYesGet one of the user's trips.

Validation rules

  • Origin, destination, start date, and end date are required.
  • End date must be on or after the start date.
  • Passwords must be at least 6 characters.
All bodies use JSON. Responses include CORS headers for CLIENT_ORIGIN.

8. Authentication

  • Passwords are hashed with Node's scrypt (per-user random salt) and compared with timingSafeEqual.
  • A custom token is created: base64url JSON payload { sub, exp } + HMAC-SHA256 signature using TOKEN_SECRET. Expiry: 7 days.
  • The frontend sends the token as Authorization: Bearer <token>.
  • The frontend stores auth state in localStorage:
KeyValue
tripguard-auth-tokenthe bearer token
tripguard-authenticated"true" flag
tripguard-userJSON user object

Protected routes in the frontend redirect unauthenticated users to /login.

9. Trip Plan Generation

The backend's buildTripPlan(input) function produces a deterministic demo plan:

Cost estimation formulas

Component

  • Accommodation
  • Food
  • Local Transport
  • Sightseeing & Activities
  • Round Trip Travel
  • Miscellaneous

Formula

  • 95 × days
  • 40 × days × people
  • 25 × days × people
  • 45 × days × people
  • 250 × people
  • 10% of subtotal

Output

  • itineraryId — trip-<uuid>, unique per trip.
  • safetyScore — 78 if preferences mention "adventure", otherwise 88.
  • safetyAlerts — three standard travel-safety alerts.
  • emergencyInfo — Emergency 112, Police 100, Ambulance 108.
  • hotels — three demo hotels (Grand Hotel / Comfort Stay / Premium Resort) with Google Maps links.
  • optimizedItinerary — one entry per travel day.

10. Weather Service

The backend proxies Open-Meteo (no API key required):

  1. Geocoding lookup: https://geocoding-api.open-meteo.com/v1/search?name={query}
  2. Forecast fetch: https://api.open-meteo.com/v1/forecast?latitude=..&longitude=.. for current temperature, wind, weather code, and 5-day daily forecast.
  3. Weather codes are mapped to human-readable conditions (Clear, Rain, Thunderstorm, etc.).

Used by the dashboard quick weather check and by the chatbot's weather answers.

11. Safety Chatbot

POST /api/chat with a message and optional tripId. The reply engine is keyword-based:

KeywordsAnswer provides
emergency / police / ambulanceIndia emergency numbers (112, 100, 108) + embassy advice
night / darkNight-safety advice for the trip destination
weather / rain / temperatureLive Open-Meteo weather for the destination
document / passport / carryDocuments & essentials checklist
transport / taxi / cabVerified transport safety tips
fallbackUses the trip's safety score + first safety alert, else generic advice

Trip lookup is scoped to the authenticated user: Trip.findOne({ _id: tripId, userId }).

14. Setup & Running

Prerequisites

  • Node.js 18+ (20+ recommended)
  • MongoDB (Atlas cluster or local server)

1. Backend

cd "backend"
npm install
# copy .env.example to .env and set MONGODB_URI + TOKEN_SECRET
npm run dev

Expected output:

MongoDB connected: tripguard_ai
TripGuard API running at http://localhost:4000

Health check: open http://localhost:4000/api/health → {"ok":true,"database":"connected"}

2. Frontend

cd "frontend"
npm install
npm run dev

Frontend runs at http://localhost:5173.

Scripts

Backend

  • npm run dev — watch mode (node --watch server.js)
  • npm start — plain start

Frontend

  • npm run dev — Vite dev server
  • npm run build — production build
  • npm run preview — preview built output
  • npm run lint — ESLint

15. Security Notes

  • Never put MONGODB_URI or TOKEN_SECRET in the React frontend.
  • Never commit backend/.env to the repository (a .gitignore is provided).
  • Change TOKEN_SECRET before any deployment.
  • Passwords use scrypt; tokens are signed with HMAC-SHA256 and expire after 7 days.
